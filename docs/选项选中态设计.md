# 选项卡片「选中态」设计拆解

> **素材**：`参考图/quizPage.jpg`（1260 × 904 px，选项区局部，第 4 项为选中态）
> **对照**：`参考图/questions.jpg` 中同组件的未选中态
> **版本**：v1.0（2026-11-06）｜配套文档：[答题页布局说明.md](./答题页布局说明.md)

## 0. 结论速览

| 问题 | 结论 |
| --- | --- |
| 选中态改了什么？ | **只改了 3 个颜色**：描边、底色、文字/字母 |
| 有没有对钩 / 单选圆点？ | **没有**。整张卡片就是选择器 |
| 边框会不会加粗？ | **不会**。选中前后描边厚度完全一致（≈2 物理 px） |
| 字重 / 字号 / 位置会变吗？ | **不变**。基线偏移同为「卡片顶 +105 px」 |
| 有没有阴影 / 发光？ | **没有**。边缘 3–4 px 的淡青是 JPEG 色度扩散 |
| 用的蓝色是哪个？ | 与主按钮**同一个主色 `#0099FF`**（描边、字母、文字三处一致） |
| 底色怎么来的？ | `#F2FBFF` ≈ 主色以 **5% 不透明度**叠在白底上（`rgba(0,153,255,.05)`） |
| 最大的问题 | 选中态文字对比度仅 **2.86 : 1**（远低于 WCAG AA 4.5:1） |

## 1. 先纠正一个前提：quizPage 与 questions 不是同一道题

最初以为两张图是"同一页面、不同状态"，实测**不是**：两张图的选项文案完全不同。

| 位置 | questions.jpg（第 3 题） | quizPage.jpg（另一题） |
| --- | --- | --- |
| A | hypothesis | was built |
| B | provokes | built |
| C | transmit | was collapsed |
| D | yield | **collapsed（选中）** |

所以准确的关系是：**同一个页面模板 / 同一个选项组件，两道不同的题**。

这对规范的影响是正面的 —— 两张图可以互相校验组件一致性，实测也确实完全一致：

| 校验项 | questions.jpg | quizPage.jpg | 结论 |
| --- | --- | --- | --- |
| 卡片外框 x | 50 – 1208 | 50 – 1208 | 同 |
| 卡片高度 | 174 | 174 | 同 |
| 卡片间距 | 44 | 44 | 同 |
| 字母墨迹起点 x | 102 / 106 / 103 / 106 | 102 / 106 / 103 / 106 | **逐字完全一致** |
| 文字墨迹起点 x | 192 / 192 / 189 / 189 | 189 / 192 / 189 / 191 | 一致（189–192，随首字母字形侧边距浮动） |
| 基线偏移（字母底 − 卡顶） | 105 / 105 / 105 / 105 | 105 / 105 / 105 / 105 | **完全一致** |

> 也就是说：**选中态不会改变组件的任何几何量**，这本身就是一条可用于验收的硬结论。

## 2. 像素级测量（quizPage.jpg，1260 px 宽）

### 2.1 几何

         │                                                          │

         │  ↑        ↑                                              │

| 卡片外框 | x 50 – 1208，y 682 – 856 | 386 × 58 dp |
| 卡片宽 / 高 | 1159 × 174 px | — |
| 圆角 | 8 px（四角一致） | 2.7 dp |

| 文字基线 | y ≈ 787 → **卡片顶 +105 px**（其余三项同为 +105） | ≈35 dp |
| 文字垂直中心 | (748+787)/2 = 767.5 vs 卡片中心 769 | 基本居中 |

### 2.2 颜色（含 JPEG 失真校正）

JPEG 的 4:2:0 色度二次采样会把 1–2 px 宽的细线"洗淡"：实测描边核心像素是 `(96,147,166)`、字母最饱和像素是 `(12,151,242)`，看起来都不像纯蓝。但**亮度（luma）不受色度采样影响**：

| 采样点 | 实测 RGB | luma | 参考色 luma | 判定 |
| --- | --- | --- | --- | --- |
| 描边核心 | (96,147,166) | 133.9 | — | 覆盖率 ≈89% 的混色 |
| 主色 `#0099FF` | (0,153,255) | **118.9** | 118.9 | — |
| 选定字母最饱和像素 | (12,151,242) | 119.8 | 118.9 | ✅ 即 `#0099FF` |
| 选中文字最暗像素 | (38,139,188) | 114.4 | 118.9 | ✅ 即 `#0099FF` |
| 选中底色 | (242,251,255) | 248.8 | `#F2FBFF` | ✅ 大面积取色可信 |
| 主按钮实心区（questions） | (1,153,254) | 119.4 | 118.9 | ✅ 与选项同一主色 |

结论：**选中态的描边、字母、文字用的都是主色 `#0099FF`**，视觉上偏"灰蓝"完全是 JPEG 的锅，不要照着截图取色 #1F8FD0 之类。

### 2.3 底色与主色的关系

`#F2FBFF` 与「白色 + 主色 α」的拟合：

| α | 计算值 |
| --- | --- |
| 3% | `#F7FCFF` |
| 4% | `#F5FBFF` |
| **5%** | **`#F2FAFF`**（实测 `#F2FBFF`，仅 G 通道差 1） |
| 6% | `#F0F9FF` |

→ 可写成 `background: rgba(0, 153, 255, 0.05)`，或直接写死 `#F2FBFF`。

## 4. 视觉细节逐项核验

### 4.1 没有对钩、没有单选圆点

对整张卡片做墨迹扫描，除字母 `D` 与单词 `collapsed` 外没有任何其他深色像素；右侧（x 500–1200）完全空白。

→ 可点击区域 = 整卡（1159 × 174 ≈ 386 × 58 dp），不存在"小圆点 + 文本"的传统 radio 结构。

### 4.2 描边没有变粗

沿四条边做法向积分（把颜色差值还原成"等效像素厚度"）：

| 边 | 默认态（卡 A） | 选中态（卡 D） |
| --- | --- | --- |
| 上 | 1.95 px | 2.05 px |
| 左 | 2.09 px | 1.92 px |
| 右 | — | 1.91 px |
| 下 | — | 1.89 px |

→ 两态厚度相同（≈2 物理 px，视觉上比 CSS 1px 略细）。**选中不靠"加粗边框"来强化**。

### 4.3 没有外发光

选中卡边缘外侧 3–4 px 内出现浅青过渡（y 679→681 依次为 `(249,255,255)` → `(232,253,255)` → `(216,250,255)`，亮度只下降 5–15，属于极低覆盖率），但：

- 卡片内侧的过渡在 4 px 内就收敛到填充色 `#F2FBFF`；
- 默认态同样有约 4 px 的过渡（灰阶 `253 → 237 → 245 → 250`）；
- 两者的过渡宽度差异仅 1–2 px，符合 JPEG 8×8 DCT 振铃 + 色度扩散的表现。

→ 判定为**压缩伪影，不是设计上的 glow**。实现时用实线描边即可；若觉得太"平"，可加 `box-shadow: 0 0 0 1px rgba(0,153,255,.12)`，但那是增强、不是还原。

### 4.4 字重没有变

在字母中线处量竖笔画宽度：`A` 4–5 px、`B` 5 px、`C` 5 px、`D` 4–5 px —— 选中项没有加粗。

### 4.5 文字没有位移

| 卡片 | 顶边 | 字母基线 | 偏移 |
| --- | --- | --- | --- |
| A | 27 | 132 | +105 |
| B | 245 | 350 | +105 |
| C | 464 | 569 | +105 |
| D（选中） | 682 | 787 | +105 |

→ 四张卡片的基线偏移完全一致（±1 px 抗锯齿误差），切换选中时文字不会"跳"，这对列表连续点击的稳定性很重要。

### 4.6 填充是纯色，不是渐变

在卡片内取 6 列 × 8 行的采样网格，全部为 `(242,251,255)`，纵向无渐变（顶部 `243,250,255` 只是边缘抗锯齿）。

## 5. 可访问性分析（值得产品注意）

用 WCAG 2.1 相对亮度公式计算：

| 场景 | 前景 | 背景 | 对比度 | 结论 |
| --- | --- | --- | --- | --- |
| 默认态文字 | `#262626` | `#FCFCFC` | **14.75 : 1** | ✅ AAA |
| 选中态文字 | `#0099FF` | `#F2FBFF` | **2.86 : 1** | ❌ 低于 AA（4.5），也低于 AA-Large（3.0） |
| 选中态描边 | `#0099FF` | `#FFFFFF` | 3.00 : 1 | ⚠️ 勉强达到"非文本 UI 组件"3:1 要求 |

点击选中后，文字对比度从 14.75 掉到 2.86——**"选中"这个动作反而让内容更看不清了**。这是该设计的真实缺陷。

改进方案（按对原设计的破坏程度排序）：

| 方案 | 做法 | 影响 |
| --- | --- | --- |
| A（推荐，改动最小） | 文字/字母保持蓝色但加深到 `#0072C6`（对比度 ≈ 4.8:1），描边仍用 `#0099FF` | 与截图有轻微色差 |
| B | 文字保持深灰 `#262626`，只有描边+底色变蓝 | 选中感变弱，但完全达标 |
| C | 文字 `#0099FF`，同时加粗到 500 或加 0.2px 描边 | 视觉重量变化，破坏"不加粗"的现有规范 |

还原截图优先 → 采用原方案；面向真实用户 → 建议 A。

## 6. 实现规范

### 6.1 设计令牌

```css
:root {
  /* 颜色 */
  --option-bg:            #FCFCFC;              /* 默认底色 */
  --option-border:        #E9E9E9;              /* 默认描边 */
  --option-text:          #262626;              /* 默认文字 */
  --option-selected-bg:   #F2FBFF;              /* = rgba(0,153,255,.05) 叠白 */
  --option-selected-line: #0099FF;              /* 描边 / 文字 / 字母同色 */
  --option-selected-text: #0099FF;              /* 可访问性改进时改成 #0072C6 */

  /* 几何 */
  --option-height:     58px;    /* 174 px @3x */
  --option-radius:     2.67px;  /* 8 px @3x */
  --option-gap:        14.67px; /* 44 px @3x */
  --option-pad-x:      17px;    /* 52 px @3x */
  --option-key-width:  29px;    /* 87 px @3x */
  --option-border-w:   1px;     /* 参考图 ≈2 物理 px（≈0.67dp），1px 会略粗，可接受 */
}
```

## 附录 B：取色避坑指南

用吸管工具或取色器直接点截图上的选中项，会得到类似 `#268ABE`、`#1F8FD0`、`#2A8FC8` 的"脏蓝"。原因：

1. **JPEG 4:2:0 色度二次采样**：色度分辨率只有亮度的一半，1–2 px 的细线会被白底"洗淡"；
2. **抗锯齿**：细笔画几乎没有 100% 覆盖的像素；
3. **截图缩放**：非整数倍缩放会进一步混合。

正确做法：先看**大面积纯色**（如主按钮 `#0199FE`、选中卡填充 `#F2FBFF`），再用 **luma 匹配**反推细线颜色（本例 luma 118.9 精确命中 `#0099FF`）。
